## 0. 短命攻击弹幕的生命周期管理

状态机里凡是「进入某动作就生成一个短命弹幕（挥砍/前摇/特效）」的设计，必须保证**任意时刻最多一个实例**。

- **进入动作前**：先 Kill 上一发再生成。不能只靠覆盖索引——旧弹幕会变孤儿，活到 `timeLeft` 自然结束，与新的并存。
- **退出动作时**：同样 Kill 一次并清索引，双保险覆盖所有转出路径。
- **索引字段**：生成后存索引，Kill 时校验类型匹配再 `Kill()`，清回 -1。

**适用条件**：挥砍、蓄力、前摇等「一次动作 = 一个弹幕」的攻击。

**关键坑**：
- 击退类攻击不要用「目标位移」当提前转出条件——击退是自己造成的，会自激（位移 → 提前转出 → 又生成弹幕 → 更大击退）。挥砍期间固定挥满整段，挥完再重新走位。
- 命中冷却 `localNPCHitCooldown` 要 ≥ 攻击持续帧数，否则单个弹幕对同一目标也会多次判定。

## 1. 三层状态机：动作包 / 状态数据包 / 检测门

把状态机拆成三层，是本项目解决「状态与判定耦合」的核心手法。

- **状态数据包（Context）**：一个类集中保存全部可变状态（引用、模式、动作、计时器、缓存），配合 `InstancePerEntity = true` 做到每实体独享一份。它是唯一真相源。
- **检测门（Gates）**：全静态纯函数，只读 Context，只回答是/否（或纯几何计算）。所有判定阈值也集中在这里，调参只改一处。
- **动作包（Actions）**：每个动作只做两件事——本帧怎么动、满足哪个门就切到哪个动作。静态无状态，只读写传入的 Context。
- **调度器（薄）**：`PostAI` 只做「刷新 Context → 跑模式门决定是否切换 → 调 `Actions.Run`」。

**适用条件**：状态多、判定条件多、且判定与状态容易互相干扰的 AI（宠物 / 随从 / 敌人行为）。

**关键收益 / 坑**：
- 模式切换只读计时门，攻击触发只读位置门——**两类判定彻底解耦**，避免「切换条件与走位条件互斥」的死结（本项目就栽在这上面，见 log.md Bug 3）。
- 所有动作读同一个 Context，避免状态散落在多个字段导致不同步。
- 坑：不要在每个动作里重复硬编码阈值，统一放检测层；否则调参要改多处、易漏。

## 2. 目标锁定（ResolveTarget）

- 玩家标记目标（`OwnerMinionAttackTargetNPC`）最高优先，可随时强制切换。
- 否则沿用已锁定目标（`whoAmI` 缓存），只要它还活着、可追击、在索敌范围内。
- 只有锁定目标失效才重新找最近的。

**适用条件**：多敌人场景，需要攻击连贯、不来回跳目标。

**关键坑**：不要在每帧用「最近距离」重选目标——目标会在相邻敌人间跳变（见 log.md Bug 2）。锁定要在目标失效时才解除。

## 3. slab 法求贴边接触点（GetContactPoint）

从敌人中心朝宠物方向作射线，用 slab 法分别算射线到「敌人矩形边界」和「宠物矩形边界」的距离，取两轴较小者相加，再加间隙 `ContactGap`，得到宠物中心应落的位置。

```
dir = normalize(pet.Center - target.Center)
ax, ay = abs(dir.X), abs(dir.Y)
enemyReach = min(target.width/2 / ax, target.height/2 / ay)
petReach   = min(pet.width/2   / ax, pet.height/2   / ay)
contact    = target.Center + dir * (enemyReach + petReach + ContactGap)
```

**适用条件**：需要 A 精确贴在 B 边框外而不重合（近战贴边、绕障碍悬停）。

**关键收益 / 坑**：
- 对细长敌人 / BOSS 也能贴准，比「用最大边长当半径的圆近似」更准。
- 坑：贴边后两者不再 hitbox 相交——所有依赖「相交」的判定要同步改成「到接触点距离」判定，否则会失效（见 log.md Bug 2 的 `UpdateMode` 修正）。

## 4. 远程站位区间控制（MaintainStandOff）

远程攻击不要一路 `SteerTo(目标中心)`，而是维持一个距离区间 `[Min, Max]`：
- 太远 → 朝目标靠近
- 太近 → 朝远离目标方向后退
- 区间内 → 减速悬停

**适用条件**：远程单位需要拉开距离输出（丢投射物、放法术）。

**关键坑**：没有站位概念的单位会一路挤到目标中心，既失去远程的意义，又和「贴边才能切近战」之类的判定打架（见 log.md Bug 3）。区间值要考虑攻击射程与前摇期间目标位移。

## 5. 追击超时安全阀（MeleeChaseTimedOut）

对「N 秒后切换到贴身模式」的设计，加一个超时门：切入后若在更短时间内（如 1.5 秒）仍未达成条件（贴边），就提前切回。

**适用条件**：目标速度可能 ≥ 己方速度（冲刺 BOSS），否则会整段模式空转。

**关键收益**：把最坏情况的真空从 5 秒压到 1.5 秒，且正常战斗（几百毫秒就贴边）不会误触发。

## 6. 用 Global* 挂载改写原版内容

想给原版宠物/物品加行为，但不新建内容时：
- `GlobalProjectile.AppliesToEntity` 精确锁定目标弹幕 ID（如 `ProjectileID.Penguin`）。
- `InstancePerEntity => true` 让每个弹幕实例有独立状态。
- 保留原版跟随 AI，只在 `PostAI`（原版 AI 之后）追加自己的逻辑。

配套的还有 `GlobalItem` / `GlobalBuff`：用 `AppliesToEntity` 或 `type ==` 锁定，只替换 Tooltip / buff 文本（`ModifyTooltips` / `ModifyBuffText`），不改属性。

**适用条件**：在原版内容上做「增强版」而非全新内容。

**关键坑**：`PostAI` 里本体要 `friendly = false`，伤害全由自定义弹幕结算，避免接触伤害与弹幕伤害重复。

## 7. 召唤类实现铁律（来自 tmod-modding skill）

召唤类（宠物 / 随从 / 鞭子）要实现完整，不能只做一半：
- 鞭子索敌 + tag 加成（`MinionShot` + `SummonTagDamageMultiplier`）
- 饰品 / 药水 / 栏位加成（`GetTotalDamage` / `GetKnockback` 用 `DamageClass.Summon`）

**关键坑**：自定义攻击弹幕要登记为 `MinionShot`，否则鞭子标记加成不生效。
